# Як додати свій DAG: шлях від коду до Airflow у хмарі

Ви пишете DAG у своїй гілці, відкриваєте Pull Request, викладач його апрувить — і за кілька хвилин ваш DAG з'являється в Airflow на Railway. Так само працюють команди на реальних проєктах.

```
ваша гілка ──► Pull Request ──► перевірка (CI) ──► апрув викладача ──► merge у main ──► Railway збирає і оновлює Airflow
```

## Один раз: підготовка

1. Прийміть запрошення в репозиторій (лист від GitHub на пошту).
2. Склонуйте репозиторій і перейдіть у папку:
   ```bash
   git clone https://github.com/ihorkoo/airflow-demos.git
   cd airflow-demos
   ```
3. Підніміть Airflow локально, щоб перевіряти DAG до відправки: `docker compose up -d`, потім http://localhost:8080 (докладно — у головному [README](../README.md)).

## Щоразу: новий DAG

**1. Створіть гілку від свіжого `main`** (замініть `ivan-petrenko` на свій GitHub-логін):

```bash
git checkout main
git pull
git checkout -b ivan-petrenko/first-dag
```

**2. Додайте файл у свою папку.** Вона має називатися точно як ваш GitHub-логін (маленькими літерами):

```bash
mkdir -p dags/students/ivan-petrenko
cp templates/student_dag.py dags/students/ivan-petrenko/ivan-petrenko_hello.py
```

Відкрийте файл і змініть `STUDENT` та `dag_id`. Правила:

- `dag_id` починається з вашого логіна — так DAG-и різних студентів не конфліктують
- міняти можна тільки файли у `dags/students/<ваш_логін>/`, інші зміни перевірка відхилить
- паролів, ключів і токенів у коді не має бути ніколи; для налаштувань є `Variable`, для доступів — `Connection` (демо 13 і 14)

**3. Перевірте локально.** Airflow підхопить файл за кілька хвилин (або швидше, якщо ви додали `AIRFLOW__DAG_PROCESSOR__REFRESH_INTERVAL: "30"` у `docker-compose.yaml`). Знайдіть свій DAG за міткою з вашим логіном, запустіть і переконайтеся, що всі задачі зелені. Якщо DAG не з'явився — `docker compose logs`, там буде помилка імпорту.

**4. Закомітьте і відправте:**

```bash
git add dags/students/ivan-petrenko
git commit -m "Додав перший DAG"
git push -u origin ivan-petrenko/first-dag
```

**5. Відкрийте Pull Request.** Після `git push` у терміналі з'явиться посилання, або натисніть кнопку **Compare & pull request** на сторінці репозиторію. Заповніть чекліст у шаблоні.

**6. Дочекайтеся перевірки.** Знизу в PR з'явиться перевірка `check-dags`:

- зелена галочка — DAG імпортується, можна чекати апруву
- червоний хрестик — натисніть **Details**, прочитайте помилку, виправте файл, зробіть новий `git commit` і `git push` у ту саму гілку. PR оновиться сам

**7. Апрув і merge.** Викладач дивиться код, лишає коментарі або апрувить. Якщо є коментарі — виправте, запуште в ту саму гілку і напишіть у PR, що готово.

**8. Ваш DAG у хмарі.** Після merge Railway сам збирає новий образ. Це триває 3-5 хвилин. Відкрийте Airflow за посиланням від викладача, увійдіть під студентським логіном і знайдіть свій DAG за міткою з вашим логіном.

> Кожен деплой перезапускає Airflow, тому історія запусків у хмарному Airflow не зберігається, а всі DAG-и знову стоять на паузі. Зніміть паузу й запустіть свій DAG вручну.

## Якщо щось пішло не так

| Проблема | Що робити |
|---|---|
| `git push` каже `Permission denied` | ви ще не прийняли запрошення в репозиторій, перевірте пошту |
| Перевірка пише «Файл поза вашою папкою» | у PR потрапили чужі файли: перенесіть свої зміни у `dags/students/<ваш_логін>/` |
| Перевірка пише про помилку імпорту | відкрийте Details, там номер рядка й текст помилки |
| DAG не видно в хмарному Airflow | перевірте, що PR змерджений і деплой у Railway завершився; потім оновіть сторінку |
| Код з інтернету не працює | здебільшого це Airflow 2, а тут третя версія: таблиця відмінностей є в головному README |
