# Демо 2. Класичні оператори

Файл: [`dags/demo_02_operators.py`](../dags/demo_02_operators.py)

## Ідея

Оператор — це готовий шаблон задачі. `@task` із [демо 1](demo_01_basics.md) — теж оператор, просто створений з вашої функції. Різниця в тому, звідки береться робота: у `@task` ви пишете її самі, в операторі вона вже написана й параметризується.

Класичний синтаксис нікуди не зник і потрібен там, де TaskFlow не підходить: готові інтеграції (Postgres, S3, Spark), команди терміналу, порожні точки збірки.

## Три оператори з демо

### `EmptyOperator`

Нічого не робить. Потрібен як точка входу/виходу графа, щоб десять задач не малювали сорок стрілок до десяти інших.

```python
start = EmptyOperator(task_id="start")
```

### `BashOperator`

Виконує команду в оболонці.

| Параметр | Значення за замовч. | Що робить |
|---|---|---|
| **`bash_command`** | обов'язковий | Команда або шлях до `.sh`. Підтримує Jinja-шаблони |
| `env` | `None` | Словник змінних середовища. За замовчуванням замінює середовище цілком |
| `append_env` | `False` | `True` — додати `env` до наявного середовища, а не замінити |
| `cwd` | `None` | Робоча тека |
| `output_encoding` | `utf-8` | Кодування виводу |
| `skip_on_exit_code` | `99` | Код виходу, що означає «пропустити задачу», а не «помилка» |
| `output_processor` | остання строка | Функція, що перетворює stdout перед відправкою в XCom |

У XCom потрапляє **останній рядок** stdout. Це часте джерело сюрпризів: якщо команда друкує багато, наступна задача отримає лише хвіст.

Пастка з пробілом: якщо `bash_command` закінчується на `.sh`, Airflow вважає це шляхом до файлу-шаблону. Щоб виконати рядок, що закінчується на `.sh`, додайте пробіл у кінці.

### `PythonOperator`

Викликає функцію, оголошену поза DAG-ом.

| Параметр | Значення за замовч. | Що робить |
|---|---|---|
| **`python_callable`** | обов'язковий | Функція. Без дужок — передаємо саму функцію, не результат |
| `op_args` | `None` | Позиційні аргументи списком |
| `op_kwargs` | `None` | Іменовані аргументи словником |
| `templates_dict` | `None` | Значення, які проженуть через Jinja і покладуть у контекст |
| `templates_exts` | `None` | Розширення файлів, що вважаються шаблонами |
| `show_return_value_in_logs` | `True` | Друкувати результат у логах. Вимикайте, якщо там секрети чи мегабайти |

## `>>` — стрілки вручну

Оператори не передають результат один одному, тому порядок задається явно:

```python
start >> [show_date, count_files] >> greet >> finish
```

| Запис | Означає |
|---|---|
| `a >> b` | `b` після `a` |
| `a << b` | `a` після `b` |
| `a >> [b, c]` | `b` і `c` паралельно після `a` |
| `[b, c] >> d` | `d` чекає обох |
| `a.set_downstream(b)` | те саме, що `a >> b` |
| `chain(a, b, c)` | ланцюжок без стрілок, зручно для довгих послідовностей |

Список у списку (`[a, b] >> [c, d]`) не працює — Airflow не будує декартів добуток. Для цього є `cross_downstream`.

## Коли що брати

| Задача | Інструмент |
|---|---|
| Власна логіка на Python | `@task` |
| Викликати готову функцію з іншого модуля | `PythonOperator` або `@task` поверх неї |
| Команда терміналу, скрипт | `BashOperator` або `@task.bash` |
| Точка збірки графа | `EmptyOperator` |
| SQL до бази | `SQLExecuteQueryOperator` ([демо 14](demo_14_postgres.md)) |

## Типові помилки

| Симптом | Причина |
|---|---|
| Задача виконалась при розборі DAG-а | Написали `python_callable=say_hello()` з дужками |
| `Duplicate task_id` | Два оператори з однаковим `task_id` |
| BashOperator не бачить файл | Шлях усередині контейнера, а не на вашому комп'ютері |
| У XCom від Bash не те значення | Береться лише останній рядок stdout |

## Що спробувати

- Додати `bash_command="exit 99"` і побачити статус `skipped` замість `failed`.
- Замінити `PythonOperator` на `@task` — граф лишиться той самий.
