# Демо 1. Базовий DAG і TaskFlow

Файл: [`demo_01_basics.py`](demo_01_basics.py)

## Ідея

DAG (Directed Acyclic Graph) — це опис *що* і *в якому порядку* запускати. Він не виконує роботу сам, а описує граф задач: вершини — задачі, стрілки — залежності. «Ациклічний» означає, що повернутися назад по стрілках неможливо; цикл Airflow просто не прийме.

Підхід TaskFlow (декоратори `@dag` і `@task`) — стандарт для Airflow 3. Ви пишете звичайні функції, а Airflow сам будує з них граф.

## Як воно працює

```python
@dag(dag_id="demo_01_basics", start_date=datetime(2025, 1, 1), schedule=None, catchup=False)
def demo_01_basics():
    @task
    def extract() -> list[int]: ...

    numbers = extract()      # це НЕ виклик функції
    total = transform(numbers)

demo_01_basics()             # без цього рядка DAG не з'явиться
```

Три речі, які треба зрозуміти одразу:

1. **`extract()` нічого не виконує.** У момент розбору файлу цей виклик лише створює об'єкт задачі й повертає посилання на її майбутній результат (`XComArg`). Сама функція запуститься пізніше, в окремому процесі, можливо на іншій машині.
2. **Залежності виводяться з даних.** Ви передали результат `extract()` у `transform()` — Airflow зрозумів, що `transform` чекає на `extract`. Малювати стрілки вручну не треба.
3. **Останній рядок обов'язковий.** `@dag` створює *фабрику*. Поки її не викликали, об'єкта DAG не існує і в інтерфейсі нічого не буде. Це помилка №1 у новачків.

## Довідка: параметри `@dag`

Повний список Airflow 3.3.1. Жирним — те, що використовують постійно.

| Параметр | Значення за замовч. | Що робить |
|---|---|---|
| **`dag_id`** | обов'язковий | Унікальне ім'я. Має збігатися з іменем функції — не вимога, але сильна конвенція |
| **`start_date`** | — | З якої дати Airflow рахує запуски. Дата в минулому + `catchup=True` = лавина запусків |
| **`schedule`** | `None` | Розклад: `None`, `"@daily"`, cron, timedelta, Asset (див. [демо 12](../demo_12_schedule/README.md)) |
| **`catchup`** | з конфігу | Чи доганяти пропущені інтервали від `start_date` |
| **`tags`** | `[]` | Мітки для фільтра в інтерфейсі |
| `description` | `None` | Короткий опис, видно у списку DAG-ів |
| `doc_md` | `None` | Markdown-документація, показується на сторінці DAG-а |
| **`default_args`** | `{}` | Словник параметрів, що застосовуються до всіх задач (див. [демо 7](../demo_07_retries/README.md)) |
| `end_date` | `None` | Після цієї дати запуски не створюються |
| **`max_active_runs`** | з конфігу | Скільки запусків DAG-а можуть іти одночасно |
| `max_active_tasks` | 16 | Скільки задач цього DAG-а можуть іти одночасно |
| `max_consecutive_failed_dag_runs` | з конфігу | Після N провалів поспіль DAG ставиться на паузу |
| `dagrun_timeout` | `None` | Убити запуск, якщо він триває довше |
| `fail_fast` | `False` | Перша ж провалена задача зупиняє весь запуск |
| `params` | `None` | Параметри, які можна ввести руками при запуску («Trigger DAG w/ config») |
| `on_success_callback` / `on_failure_callback` | `None` | Функція, що викликається при завершенні запуску |
| `is_paused_upon_creation` | `None` | Створити DAG уже знятим з паузи |
| `dag_display_name` | `dag_id` | Показувана назва, може містити пробіли й емодзі |
| `template_searchpath` | `None` | Де шукати `.sql` та інші файли-шаблони |
| `render_template_as_native_obj` | `False` | Шаблон повертає Python-об'єкт, а не рядок |
| `user_defined_macros` / `user_defined_filters` | `None` | Власні функції для Jinja-шаблонів |
| `access_control` | `None` | Права ролей на цей DAG |
| `owner_links` | `{}` | Зробити ім'я власника посиланням |

## Довідка: параметри `@task`

`@task` приймає **усі** параметри оператора. Найчастіші:

| Параметр | Значення за замовч. | Що робить |
|---|---|---|
| `task_id` | ім'я функції | Перевизначити ім'я задачі |
| **`retries`** | 0 | Скільки разів повторити при помилці |
| **`retry_delay`** | 5 хв | Пауза між спробами |
| **`trigger_rule`** | `all_success` | Умова запуску (див. [демо 8](../demo_08_trigger_rules/README.md)) |
| `execution_timeout` | `None` | Убити задачу, якщо триває довше |
| `depends_on_past` | `False` | Не запускати, поки та сама задача за попередній період не завершилась успішно |
| `multiple_outputs` | `False` | Якщо функція повертає `dict` — розкласти його на кілька окремих XCom |
| `do_xcom_push` | `True` | Чи класти `return` в XCom узагалі |
| `pool` / `pool_slots` | `default` / 1 | Обмеження паралелізму через пули |
| `priority_weight` | 1 | Пріоритет у черзі |
| `queue` | `default` | На якого воркера відправити |
| `max_active_tis_per_dag` | `None` | Скільки копій цієї задачі можуть іти одночасно |
| `task_display_name` | `task_id` | Показувана назва |
| `doc_md` | `None` | Документація задачі в інтерфейсі |
| `map_index_template` | `None` | Як підписувати копії динамічної задачі ([демо 9](../demo_09_dynamic_tasks/README.md)) |

Усі варіанти декоратора: `@task`, `@task.branch`, `@task.short_circuit`, `@task.sensor`, `@task.bash`, `@task.virtualenv`, `@task.external_python`, `@task.docker`, `@task.kubernetes`, `@task.run_if`, `@task.skip_if`.

## Типові помилки

| Симптом | Причина |
|---|---|
| DAG не з'явився в списку | Немає виклику `demo_01_basics()` в кінці файлу |
| DAG не з'явився, файл точно на місці | Помилка імпорту — дивіться `docker compose logs` |
| `Task ... not found` | `task_id` задається іменем функції; перейменували функцію — перейменувалась задача |
| Код із туторіалу не працює | Туторіал для Airflow 2: там `from airflow.decorators import dag` і `schedule_interval` |

## Що спробувати

- Прибрати останній рядок і подивитися, як DAG зникне з інтерфейсу.
- Поміняти місцями виклики в кінці — граф не зміниться, бо порядок задають дані, а не порядок рядків.
- Додати `@task(task_id="load_to_dwh")` і побачити нову назву в графі.

## Примітка до коду

У задачі `load` стоїть `raise EOFError` — навмисний збій, щоб подивитися червону задачу і логи. Після розбору рядок можна прибрати.
