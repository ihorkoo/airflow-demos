# Демо 6. Розгалуження

Файл: [`demo_06_branching.py`](demo_06_branching.py)

## Ідея

Іноді далі треба виконати **одну гілку з кількох**: даних немає — нічого не робимо, даних мало — вантажимо одним шматком, багато — частинами. `@task.branch` приймає рішення в рантаймі й повертає `task_id` гілки, яку виконувати.

Решта гілок отримують статус `skipped` — у графі вони блідо-рожеві. Пропуск поширюється далі по графу: все, що залежало від пропущеної гілки, теж пропускається.

## Як це виглядає

```python
@task.branch
def choose_path(rows: int) -> str:
    if rows == 0:
        return "no_data"
    if rows < 1000:
        return "small_load"
    return "big_load"

branch >> [no_data(), small_load(), big_load()]
```

Повертається **рядок з іменем задачі**, а не сама задача і не дані. Можна повернути список рядків — тоді виконається кілька гілок. Можна повернути `None` — тоді пропускаються всі.

## Довідка: інструменти розгалуження

| Інструмент | Що повертає | Коли |
|---|---|---|
| **`@task.branch`** | `task_id` або список | Вибрати гілку з кількох |
| **`@task.short_circuit`** | `True` / `False` | `False` — пропустити **все** нижче. Для перевірок «чи є сенс продовжувати» |
| `@task.run_if(condition)` | — | Виконати задачу лише за умовою, інакше пропустити |
| `@task.skip_if(condition)` | — | Дзеркальний варіант |
| `@task.branch_virtualenv` | `task_id` | Те саме в окремому venv |
| `@task.branch_external_python` | `task_id` | Те саме в іншому інтерпретаторі |
| `BranchPythonOperator` | `task_id` | Класичний синтаксис |

`@task.short_circuit` має параметр `ignore_downstream_trigger_rules` (за замовчуванням `True`): при `False` пропускається лише безпосередньо наступна задача, а не весь хвіст графа.

## Головна пастка: збірка після розгалуження

Якщо після гілок поставити спільну задачу, вона **не запуститься**. Причина: правило за замовчуванням `all_success` вимагає, щоб усі попередні були успішні, а дві з трьох гілок — `skipped`.

```python
branch >> [a, b, c] >> finish                    # finish НЕ запуститься

@task(trigger_rule="none_failed_min_one_success")
def finish(): ...                                 # ось так запуститься
```

`none_failed_min_one_success` читається так: «жодна попередня не впала і хоча б одна відпрацювала успішно» — пропущені не рахуються за провал. Це стандартне правило для точки збірки після розгалуження. Детальніше — [демо 8](../demo_08_trigger_rules/README.md).

## Типові помилки

| Симптом | Причина |
|---|---|
| Усі гілки пропущено | Повернули назву задачі, якої немає, або `None` |
| Повернули функцію, а не рядок | Треба `return "small_load"`, не `return small_load` |
| Задача після гілок не запускається | Потрібен `trigger_rule="none_failed_min_one_success"` |
| Гілка в `TaskGroup` не знаходиться | Ім'я має бути повне: `"група.задача"` |
| Гілка виконалась, хоч не мала | `task_id` гілки збігся з іншим |

## Що спробувати

- Поміняти `rows` на `0` і подивитися, як активною стане гілка `no_data`.
- Додати після гілок спільну задачу без `trigger_rule` — побачити, що вона не стартує. Потім додати правило.
