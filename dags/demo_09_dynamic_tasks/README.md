# Демо 9. Динамічні задачі (dynamic task mapping)

Файл: [`demo_09_dynamic_tasks.py`](demo_09_dynamic_tasks.py)

## Ідея

Кількість задач не завжди відома, коли пишеш код. У папці може бути 3 файли, а завтра 300. Динамічне відображення створює стільки копій задачі, скільки елементів прийшло у списку — і робить це **в момент запуску**, а не при розборі файлу.

У графі це одна вершина з лічильником `[4]`, усередині — окремі запуски з індексами 0, 1, 2, 3.

## Як це виглядає

```python
@task
def list_files() -> list[str]:
    return ["orders.csv", "customers.csv", "products.csv"]

@task
def process_file(file_name: str) -> int: ...

results = process_file.expand(file_name=list_files())
total(results)          # отримає список результатів усіх копій
```

`expand` приймає список і розкладає його по копіях. Задача-збирач отримує звичайний список Python.

## Довідка: методи відображення

| Метод | Приймає | Результат |
|---|---|---|
| **`.expand(arg=список)`** | список або XComArg | По копії на елемент |
| `.expand(a=[1,2], b=[3,4])` | кілька списків | **Декартів добуток**: 4 копії, не 2 |
| **`.expand_kwargs(список_словників)`** | `[{"a":1,"b":2}, ...]` | По копії на словник — коли треба пари значень, а не добуток |
| **`.partial(arg=значення)`** | одне значення | Аргумент, однаковий для всіх копій |
| `.override(task_id=..., retries=...)` | параметри задачі | Змінити налаштування відображеної задачі |

Комбінація `partial` + `expand` — найчастіший запис:

```python
process_file.partial(schema="public").expand(file_name=list_files())
```

Без `.partial()` фіксований аргумент передати не вийде: усе, що йде в `expand`, вважається списком для розкладання.

## Що важливо знати

| Обмеження | Значення |
|---|---|
| Максимум копій | 1024 (`AIRFLOW__CORE__MAX_MAP_LENGTH`) |
| Порожній список | 0 копій, задача одразу `skipped` — не помилка |
| Одночасність копій | `max_active_tis_per_dag` у задачі |
| Підпис копій в інтерфейсі | `map_index_template="{{ task.op_kwargs['file_name'] }}"` |
| Вкладене відображення | Можна відображати результат відображеної задачі |

`expanded_ti_count` у контексті каже, скільки всього копій у поточної задачі.

## Індивідуальний повтор

Головна практична перевага перед циклом усередині однієї задачі: якщо впав один файл із трьохсот, повторюється **тільки він**. Обробка решти лишається успішною, і перезапускати весь пайплайн не треба.

## Чому не звичайний цикл

```python
for f in ["a.csv", "b.csv"]:      # ТАК НЕ ТРЕБА, якщо список змінний
    process(f)
```

Цей цикл виконується при **розборі файлу**, тому список має бути відомий заздалегідь і однаковий для всіх запусків. Плюс кожна ітерація — окрема задача в графі з окремим `task_id`, і зміна списку змінює структуру DAG-а заднім числом. `expand` вирішує обидві проблеми.

Цикл доречний, коли список справді статичний — наприклад, три фіксовані таблиці-довідники.

## Типові помилки

| Симптом | Причина |
|---|---|
| `Object of type ... is not iterable` | В `expand` передали не список |
| Копій більше, ніж очікували | Два аргументи в `expand` дають добуток; треба `expand_kwargs` |
| Фіксований аргумент розклався по копіях | Його треба передавати через `.partial()` |
| Задача одразу `skipped` | Список порожній |
| `Map length exceeded` | Більше 1024 елементів |

## Що спробувати

- Повернути порожній список зі `list_files` і побачити `skipped`.
- Додати `.partial(prefix="/data/")` і подивитися, як значення потрапило в усі копії.
- Відкрити вкладку **Mapped Tasks** і зайти в лог окремої копії.
