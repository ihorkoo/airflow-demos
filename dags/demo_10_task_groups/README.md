# Демо 10. Групи задач

Файл: [`demo_10_task_groups.py`](demo_10_task_groups.py)

## Ідея

Коли задач стає більше двадцяти, граф перетворюється на кашу. `TaskGroup` складає пов'язані задачі в один блок, який в інтерфейсі можна згорнути й розгорнути. На виконання це не впливає взагалі — це суто візуальна й організаційна конструкція.

Група використовується як звичайна задача: її можна ставити у стрілки, паралелити, з'єднувати.

## Як це виглядає

```python
@task_group(group_id="orders")
def orders_group():
    @task
    def extract_orders(): ...
    @task
    def clean_orders(): ...
    extract_orders() >> clean_orders()

start() >> [orders_group(), customers_group()] >> build_report()
```

## Довідка: параметри `@task_group`

| Параметр | Значення за замовч. | Що робить |
|---|---|---|
| **`group_id`** | ім'я функції | Ім'я групи, стає префіксом задач |
| `prefix_group_id` | `True` | Додавати префікс до `task_id`. При `False` імена лишаються як є |
| `tooltip` | `""` | Підказка при наведенні на блок |
| `ui_color` | `CornflowerBlue` | Колір блоку |
| `ui_fgcolor` | `#000` | Колір тексту |
| `default_args` | `{}` | Параметри для всіх задач групи |
| `group_display_name` | `group_id` | Показувана назва з пробілами |
| `doc_md` | `None` | Markdown-опис групи |
| `add_suffix_on_collision` | `False` | Додавати суфікс, якщо ім'я групи зайняте |
| `parent_group` | автоматично | Батьківська група при вкладеності |

## Префікси імен

З `prefix_group_id=True` (за замовчуванням) реальні `task_id` стають `orders.extract_orders`. Це важливо у двох місцях:

- **`@task.branch`** — повертати треба повне ім'я: `return "orders.extract_orders"`.
- **`xcom_pull(task_ids=...)`** — теж повне ім'я.

Саме завдяки префіксу дві групи можуть містити задачі з однаковими іменами функцій.

## Групи можна перевикористовувати

Оскільки група — це функція, ту саму структуру зручно застосувати до різних джерел:

```python
@task_group
def load_source(name: str):
    @task
    def extract(): print(f"витягли {name}")
    @task
    def clean(): print(f"почистили {name}")
    extract() >> clean()

for source in ["orders", "customers", "products"]:
    load_source.override(group_id=f"load_{source}")(source)
```

Групи можна вкладати одна в одну. Також існує `.expand()` для груп — динамічне створення груп за списком, аналогічно [демо 9](../demo_09_dynamic_tasks/README.md).

## Група vs окремий DAG

| Критерій | TaskGroup | Окремий DAG |
|---|---|---|
| Спільний розклад | так | ні, свій |
| Можна перезапустити окремо | ні, лише в межах запуску | так |
| Спільні залежності | природно | через Asset або сенсор |
| Різні власники / SLA | ні | так |

Правило: логічні етапи одного пайплайна — група. Незалежні пайплайни з різною періодичністю — окремі DAG-и.

## Типові помилки

| Симптом | Причина |
|---|---|
| `@task.branch` не знаходить задачу | Потрібне повне ім'я з префіксом групи |
| `Duplicate group_id` | Дві групи з однаковим ім'ям; використайте `.override(group_id=...)` |
| Група не з'явилася в графі | Забули викликати `orders_group()` |
| Задачі групи йдуть послідовно | Усередині групи залежності задаються так само, як зовні |

## Що спробувати

- Згорнути й розгорнути групу у вкладці **Graph**.
- Поставити `prefix_group_id=False` і подивитися, як зміняться імена задач.
- Додати третю групу через `.override(group_id=...)` у циклі.
